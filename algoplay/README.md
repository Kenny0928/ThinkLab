# 🎮 AlgoPlay 演算法遊樂場

讓學生**看、猜、做**演算法的每一步：先看動畫理解流程，再預測下一步，最後自己動手操作。目標不是「看過動畫」，而是學生能說出每一步**為什麼這樣做**。

> 狀態：第一版規劃（2026-09-22 建立），尚未開始實作。

## 為什麼要「看 → 猜 → 做」

演算法視覺化的研究（Hundhausen 等人 2002 年的整合分析、Naps 等人的「參與度分類」）都指出：學習成效取決於學生**參與的程度**，而不是動畫做得多精美。只看動畫的效果有限，要讓學生預測、動手操作，才會真正理解。因此每個演算法都提供三種模式：

| 模式 | 學生做什麼 | 系統做什麼 |
|---|---|---|
| 👀 看 | 播放／暫停、上一步／下一步、調整速度 | 動畫、Python 程式碼行高亮、變數面板、一句話旁白 |
| 🤔 猜 | 在關鍵步驟停下，選出下一步會發生什麼 | 答對繼續；答錯說明原因，再播放正確的一步 |
| 🕹️ 做 | 自己操作（交換兩格、選中間、點出下一個要走的格子） | 檢查每一步並記錄錯誤次數；完成後顯示比較次數與步數 |

## 第一版（v1）範圍：共用引擎＋3 個模組

| # | 模組 | 遊戲玩法 | 對應 ThinkLab 題目 |
|---|---|---|---|
| 1 | 線性搜尋 vs 二分搜尋 | 猜數字：電腦只回答「太大／太小」，比比看誰猜的次數少 | LV.2〈線性搜尋〉、Judge-016、180、204 |
| 2 | 基礎排序（氣泡／選擇／插入） | 沿用 `sort_game` 的「自己排序、記錄錯誤」玩法 | Judge-129、130、080、072 |
| 3 | BFS 走迷宮 | 在格子地圖上點出下一層會走到的格子 | Judge-197、198、LV.3 草稿 214〈最近的超商〉 |

選這三個，是因為它們的畫面都不一樣：一維陣列上的指標、元素的比較與交換、二維格子加上佇列。共用引擎能處理這三種畫面，之後新增模組就不必再改核心。

## 技術架構

純靜態 HTML／CSS／JavaScript，不需要建置步驟。和 ThinkLab 一樣，可以直接放上 GitHub Pages。

**核心概念：演算法和畫面分開。** 每個演算法寫成 generator 函式，每走一步就 `yield` 一個步驟快照；播放前先把所有步驟收集成陣列。

```js
// modules/binary-search/algo.js：只負責演算法，不碰 DOM
export function* binarySearch(arr, target) {
  let lo = 0, hi = arr.length - 1;
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
    yield { line: 4, vars: { lo, hi, mid }, focus: [mid], ask: 'compare',
            say: `看中間第 ${mid} 格：${arr[mid]}` };
    if (arr[mid] === target) { yield { line: 6, found: mid, say: '找到了！' }; return; }
    if (arr[mid] < target) lo = mid + 1; else hi = mid - 1;
  }
  yield { line: 10, found: -1, say: '範圍空了，找不到' };
}
```

這樣做的好處：

- **上一步不必另外寫**：所有步驟都已存在陣列裡，往回只是換一個索引。
- **三種模式共用同一份演算法**：「看」依序播放；「猜」在標有 `ask` 的步驟暫停出題；「做」拿學生的操作和下一個步驟比對。
- **可以自動測試**：`algo.js` 不碰 DOM，用 `node --test` 就能檢查結果，例如排序結果要和內建排序一致。

## 課堂使用的設計細節

- **程式碼面板顯示 Python**：和 ThinkLab 講義、Judge 用同一種語言，學生看得出動畫的每一步對應哪一行。
- **成本看得見**：每個模組都顯示比較次數與交換次數，學生不必先學 O(n)、O(log n) 符號，也能直接感受到差距。
- **自訂資料**：學生可以輸入自己的數列或地圖，例如直接貼上 Judge 題目的範例輸入。
- **投影模式**：大字、高對比；空白鍵播放／暫停，← → 單步，方便老師在台上講解。
- **不只靠顏色**：狀態同時用圖示或文字標示（例如排好的格子加上 ✓），色弱學生也看得懂。
- **進度保存**：和 `sort_game` 一樣使用 localStorage，只存在學生自己的瀏覽器。

## 與現有專案的關係

- **`sort_game`**（`../../../../sort_game/practice/`）：已經完成四種排序的「學生操作＋錯誤計數」。第一版的基礎排序模組會改寫它的邏輯、接上共用引擎，不從零重做。
- **ThinkLab 主站**：AlgoPlay 是主站裡的一個區塊，會隨主站一起部署。開發方式比照「流程圖實驗室」（`../test/`）：所有檔案都放在 `algoplay/` 裡，先不改主站的導覽、編輯器和題庫。穩定後再在首頁加入口，並在相關題目頁連到對應的動畫。
