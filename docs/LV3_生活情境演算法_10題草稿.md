## 214 最近的超商

**標籤**：廣度優先搜尋、網格、多源起點　**主要目標**：辨認「多個起點同時出發」可用一次 BFS 解決，不必每格各跑一次。

### 題目

城市被畫成 `R` 列 `C` 行的方格地圖。每格是下列三種之一：

- `S`：超商，可以通行。
- `.`：一般道路，可以通行。
- `#`：建築物，不能進入。

從任一格可以往上、下、左、右移動一步，不能斜走，也不能走出地圖。請算出每一格到**最近超商**的最少步數。超商本身是 0 步；建築物與走不到超商的道路都輸出 `-1`。

### 輸入格式

第一行是 `R C`。接下來 `R` 行，每行一個長度為 `C` 的字串，只包含 `S`、`.`、`#`。

### 輸出格式

輸出 `R` 行，每行 `C` 個整數，同一行以單一半形空格分隔。

### 限制

- 1 ≤ R, C ≤ 300
- 地圖中至少有一間超商

### 範例 1

輸入：

```
3 4
.S..
.#..
....
```

輸出：

```
1 0 1 2
2 -1 2 3
3 4 3 4
```

### 範例 2

輸入：

```
3 5
S.#..
..#.S
..#..
```

輸出：

```
0 1 -1 2 1
1 2 -1 1 0
2 3 -1 2 1
```

### 解法與複雜度

把**所有**超商一開始就放進佇列、距離設為 0，再做一次 BFS。BFS 逐層擴展，第一次走到某格時的步數必定最小，所以一次走訪就能填滿整張距離表。時間 O(R·C)，空間 O(R·C)。

從每格各跑一次 BFS 是 O((R·C)²)，在 300×300 會超時，這是本題要擋掉的寫法。

### 參考解答

```python
# 核心：把所有超商同時放進佇列做多源 BFS，一次走訪求出每格的最短步數。時間 O(R*C)，空間 O(R*C)。
import sys
from collections import deque
data = sys.stdin.read().split()
r, c = int(data[0]), int(data[1])
grid = data[2:2 + r]
dist = [[-1] * c for _ in range(r)]
queue = deque()
for i in range(r):
    for j in range(c):
        if grid[i][j] == 'S':
            dist[i][j] = 0
            queue.append((i, j))
while queue:
    x, y = queue.popleft()
    for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        nx, ny = x + dx, y + dy
        if 0 <= nx < r and 0 <= ny < c and grid[nx][ny] != '#' and dist[nx][ny] == -1:
            dist[nx][ny] = dist[x][y] + 1
            queue.append((nx, ny))
print('\n'.join(' '.join(map(str, row)) for row in dist))
```

### 測資設計方向

- 必測：1×1 只有一間超商、整張地圖都是超商、被建築物完全隔開的區域、只有一條細路可通、超商在四個角落、R=1 或 C=1 的長條地圖、300×300 大地圖。
- 常見錯誤殺手：對每格各跑一次 BFS（超時）；用 DFS 求最短步數（會拿到非最短路徑）；忘記建築物要輸出 `-1`；把不可到達的道路印成 0。

## 215 展場人潮高峰

**標籤**：排序、事件掃描、差分概念　**主要目標**：把區間轉成 `+1 / -1` 事件，用排序取代逐時刻統計。

### 題目

展場記錄了 `N` 位訪客的入場與離場時間。第 i 位在時刻 `a` 入場、時刻 `b` 離場，在場時間是 `a ≤ t < b`（離場當下那一刻已經不算在場）。

請找出展場內**同時在場人數的最大值**，以及**最早**達到這個人數的時刻。

### 輸入格式

第一行是 `N`。接下來 `N` 行，每行兩個整數 `a b`。

### 輸出格式

一行兩個整數：最大同時在場人數、最早達到該人數的時刻，以單一半形空格分隔。

### 限制

- 1 ≤ N ≤ 100,000
- 0 ≤ a < b ≤ 10⁹

### 範例 1

輸入：

```
4
1 5
2 3
4 8
6 9
```

輸出：

```
2 2
```

### 範例 2

輸入：

```
1
7 8
```

輸出：

```
1 7
```

### 解法與複雜度

每位訪客拆成兩個事件：`(a, +1)` 與 `(b, -1)`。依時刻排序，**同一時刻先處理 -1 再處理 +1**（因為離場那一刻不算在場）。依序累加，人數第一次超過目前最大值時記下時刻。時間 O(N log N)，空間 O(N)。

時刻上限 10⁹，不能開一條時間軸陣列逐格統計；雙層迴圈對每個時刻數人數也會超時。

### 參考解答

```python
# 核心：把入場與離場拆成事件後排序，同一時刻先離場再入場即可正確計算同時人數。時間 O(N log N)，空間 O(N)。
import sys
data = list(map(int, sys.stdin.read().split()))
n = data[0]
events = []
for i in range(n):
    start, end = data[1 + i * 2], data[2 + i * 2]
    events.append((start, 1))
    events.append((end, -1))
events.sort(key=lambda e: (e[0], e[1]))
current = 0
best = 0
best_time = 0
for time, delta in events:
    current += delta
    if current > best:
        best = current
        best_time = time
print(best, best_time)
```

> 排序鍵 `(時刻, 增減值)` 讓 `-1` 排在 `+1` 前面，剛好符合半開區間的規則。

### 測資設計方向

- 必測：N=1、所有人時間完全相同、前一位離場時刻等於後一位入場時刻（不應算重疊）、全部區間互相巢狀、最大人數出現多次（要取最早）、時刻為 0、時刻接近 10⁹、N=100,000 的大測資。
- 常見錯誤殺手：同一時刻先加後減，導致「剛好接棒」被誤算成 2 人；用 `current >= best` 更新而印出較晚的時刻；開 10⁹ 大小的陣列導致記憶體超限。

## 216 雲端硬碟路徑整理

**標籤**：堆疊、字串處理　**主要目標**：用堆疊把 `..` 對應到「退回上一層」。

### 題目

雲端硬碟的路徑一律以 `/` 開頭。路徑裡可能出現這些情況：

- 連續多個 `/`，等同一個 `/`。
- `.` 代表目前資料夾，位置不變。
- `..` 代表回到上一層；已經在最外層時再往上仍然停在最外層。

請輸出整理後的標準路徑：以 `/` 開頭、資料夾之間用單一 `/` 分隔、結尾不加 `/`。若整理後不在任何資料夾內，輸出 `/`。

### 輸入格式

一行字串 `P`，代表原始路徑。

### 輸出格式

一行字串，代表整理後的標準路徑。

### 限制

- 1 ≤ |P| ≤ 3,000
- `P` 以 `/` 開頭，只包含英文字母、數字、底線 `_`、句點 `.` 與斜線 `/`
- 資料夾名稱不會是空字串，也不會只由句點組成（`.` 與 `..` 除外）

### 範例 1

輸入：

```
/photo/2026//trip/../dessert/./
```

輸出：

```
/photo/2026/dessert
```

### 範例 2

輸入：

```
/a/../../b//c/..
```

輸出：

```
/b
```

### 解法與複雜度

用 `/` 切開字串後逐段處理：空字串與 `.` 直接略過，`..` 就從堆疊彈出一層（堆疊空的時候不做事），其他名稱推入堆疊。最後把堆疊用 `/` 接起來並在前面補 `/`。時間 O(|P|)，空間 O(|P|)。

### 參考解答

```python
# 核心：以斜線切開路徑，用堆疊處理 . 與 ..，堆疊即為整理後的資料夾層級。時間 O(L)，空間 O(L)。
import sys
path = sys.stdin.readline().strip()
stack = []
for part in path.split('/'):
    if part == '' or part == '.':
        continue
    if part == '..':
        if stack:
            stack.pop()
    else:
        stack.append(part)
print('/' + '/'.join(stack))
```

### 測資設計方向

- 必測：輸入就是 `/`、結果是 `/`（例如 `/..`）、連續多個斜線、結尾有斜線、連續多個 `..` 超出最外層、名稱中含底線與數字、名稱為 `...`（要當成一般名稱）、3,000 字元長路徑。
- 常見錯誤殺手：用字串取代（`replace`）處理 `..` 而破壞名稱；堆疊為空時彈出造成錯誤；輸出結尾多一個 `/`；把 `...` 誤判成上層。

## 217 志工排班點數

**標籤**：動態規劃、相鄰互斥　**主要目標**：以「前一天的兩種狀態」推出目前最佳解。

### 題目

社團在未來 `N` 天招募志工。第 i 天出勤可得 `p[i]` 點服務點數，但依規定**不能連續兩天出勤**，也可以完全不出勤。請算出最多能拿到幾點。

### 輸入格式

第一行是 `N`。第二行是 `N` 個整數 `p[1] … p[N]`。

### 輸出格式

一個整數，代表最大總點數。

### 限制

- 1 ≤ N ≤ 100,000
- 0 ≤ p[i] ≤ 10⁹

### 範例 1

輸入：

```
5
3 9 4 10 2
```

輸出：

```
19
```

（選第 2 天與第 4 天：9 + 10 = 19。）

### 範例 2

輸入：

```
1
0
```

輸出：

```
0
```

### 解法與複雜度

逐天維護兩個值：`take` 是「第 i 天出勤」的最佳點數，`skip` 是「第 i 天休息」的最佳點數。新的 `take` 只能接在前一天的 `skip` 後面，新的 `skip` 取前一天兩者的較大值。答案是最後兩者的最大值。時間 O(N)，空間 O(1)。

N 可達 10⁵，列舉所有出勤組合（2^N）不可行；每次只貪心挑最大點數的日子也會錯（範例 1 貪心先挑 10 再挑 9 會違反規則）。

### 參考解答

```python
# 核心：以「排到第 i 天的最佳點數」遞推，第 i 天只有排班或休息兩種選擇。時間 O(N)，空間 O(1)。
import sys
data = list(map(int, sys.stdin.read().split()))
n = data[0]
points = data[1:1 + n]
skip, take = 0, 0
for value in points:
    skip, take = max(skip, take), skip + value
print(max(skip, take))
```

### 測資設計方向

- 必測：N=1、N=2（只能挑一天）、N=3 且中間最大、全部為 0、全部相同、最佳解是「跳兩天」的排列（如 `5 1 1 5`）、答案超過 32 位元（多個 10⁹ 相加）、N=100,000。
- 常見錯誤殺手：只比較 `dp[i-1]` 與 `dp[i-2] + p[i]` 但初始化寫錯導致 N=1、N=2 出錯；用貪心挑最大值；累加型別溢位（Python 無此問題，但測資仍要涵蓋大數確認輸出正確）。

## 218 搜尋關鍵字修正

**標籤**：動態規劃、編輯距離、字串　**主要目標**：實作插入／刪除／替換三種操作的編輯距離，並依規則挑出唯一答案。

### 題目

購物網站要幫打錯字的使用者推薦商品。定義兩個字串的**修正距離**為：把其中一個字串變成另一個字串，所需的最少操作次數。每次操作可以是**插入一個字元**、**刪除一個字元**或**替換一個字元**。

給定使用者輸入的關鍵字 `S` 與 `N` 個商品名稱，請輸出與 `S` 修正距離最小的商品名稱與該距離。若有多個商品距離相同，輸出**字典序最小**的那一個。

### 輸入格式

第一行是關鍵字 `S`。第二行是 `N`。接下來 `N` 行，每行一個商品名稱。

### 輸出格式

一行：商品名稱與修正距離，以單一半形空格分隔。

### 限制

- 1 ≤ N ≤ 50
- 1 ≤ |S| ≤ 200，1 ≤ 每個商品名稱長度 ≤ 200
- 所有字串只包含小寫英文字母

### 範例

輸入：

```
aple
3
apple
maple
apply
```

輸出：

```
apple 1
```

（`apple` 與 `maple` 距離都是 1，字典序取 `apple`。）

### 解法與複雜度

對每個商品名稱做一次編輯距離 DP：`dp[i][j]` 是 `S` 前 i 個字元與商品名前 j 個字元的最小操作次數，轉移為

```
dp[i][j] = min(dp[i-1][j] + 1,            # 刪除
               dp[i][j-1] + 1,            # 插入
               dp[i-1][j-1] + (字元不同))  # 替換或不動
```

只保留前一列即可把空間壓到 O(|W|)。全部比完後依 `(距離, 名稱)` 取最小。時間 O(N·|S|·|W|)，最大約 50×200×200 = 2×10⁶ 次運算。

### 參考解答

```python
# 核心：以編輯距離動態規劃比對每個候選字，再依距離、字典序挑出答案。時間 O(N*|S|*|W|)，空間 O(|W|)。
import sys
data = sys.stdin.read().split()
keyword = data[0]
n = int(data[1])
words = data[2:2 + n]

def edit_distance(a, b):
    previous = list(range(len(b) + 1))
    for i in range(1, len(a) + 1):
        current = [i] + [0] * len(b)
        for j in range(1, len(b) + 1):
            cost = 0 if a[i - 1] == b[j - 1] else 1
            current[j] = min(previous[j] + 1, current[j - 1] + 1, previous[j - 1] + cost)
        previous = current
    return previous[len(b)]

best_word = None
best_distance = 0
for word in words:
    distance = edit_distance(keyword, word)
    if best_word is None or distance < best_distance or (distance == best_distance and word < best_word):
        best_word, best_distance = word, distance
print(best_word, best_distance)
```

### 測資設計方向

- 必測：有商品與 `S` 完全相同（距離 0）、兩個以上商品距離相同（驗證字典序 tie-break，且字典序小的排在輸入較後面）、長度差距很大（例如長度 1 對長度 200）、只差一次替換、只差一次插入、N=1、最大規模 50 個長度 200 的名稱。
- 常見錯誤殺手：只實作 LCS 或只算長度差；DP 邊界 `dp[i][0] = i`、`dp[0][j] = j` 初始化錯；tie-break 用輸入順序而非字典序；滾動陣列覆寫順序寫錯。

## 219 共同空檔時段

**標籤**：雙指標、區間合併　**主要目標**：同時掃描兩條已排序的區間序列，找出合併後的空隙。

### 題目

小安與小宇要約一場長度為 `D` 分鐘的會議，可用時間是今天的 `0` 到 `T` 分鐘。兩人各自提供忙碌時段，時段以 `[start, end)` 表示：`start` 那一刻開始忙，`end` 那一刻起恢復空閒。

請找出**最早**可以開始的會議時間點 `s`，使得 `[s, s + D)` 這段時間兩人都有空，且 `s + D ≤ T`。若找不到，輸出 `-1`。

### 輸入格式

第一行是 `n m T D`，分別是小安的忙碌時段數、小宇的忙碌時段數、當天總長度與會議長度。接下來 `n` 行是小安的時段，每行 `start end`；再接下來 `m` 行是小宇的時段。

兩人各自的時段都已依 `start` 由小到大排序，且同一個人的時段互不重疊。

### 輸出格式

一個整數，代表最早可開始的時刻；無解輸出 `-1`。

### 限制

- 1 ≤ n, m ≤ 50,000
- 1 ≤ T ≤ 10⁹，1 ≤ D ≤ T
- 0 ≤ start < end ≤ T

### 範例 1

輸入：

```
2 2 100 20
0 30
50 60
20 40
80 90
```

輸出：

```
60
```

（合併後的忙碌時段是 `[0,40)`、`[50,60)`、`[80,90)`；空檔 `[40,50)` 只有 10 分鐘不夠，`[60,80)` 剛好 20 分鐘。）

### 範例 2

輸入：

```
1 1 10 5
0 8
3 10
```

輸出：

```
-1
```

### 解法與複雜度

兩條序列都已排序，用雙指標每次取出 `start` 較小的時段往前推進，維護「目前已知的忙碌邊界」`free_start`：

- 若新時段的 `start > free_start`，中間就是一段共同空檔，長度為 `start - free_start`，夠長就立刻回答（因為是由早到晚掃描，第一個成立的就是最早）。
- 否則把 `free_start` 更新為 `max(free_start, end)`。

所有時段處理完後，還要檢查最後一段 `[free_start, T)`。時間 O(n + m)，空間 O(1)。

時間上限 10⁹，逐分鐘檢查會超時；先把兩份時段合併後重新排序是 O((n+m) log(n+m))，可行但沒有利用「已排序」這個條件。

### 參考解答

```python
# 核心：雙指標合併兩人的忙碌時段，合併後的空隙就是共同空檔。時間 O(N + M)，空間 O(1)。
import sys
data = list(map(int, sys.stdin.read().split()))
n, m, total, need = data[0], data[1], data[2], data[3]
base = 4
first = [(data[base + i * 2], data[base + i * 2 + 1]) for i in range(n)]
base += n * 2
second = [(data[base + i * 2], data[base + i * 2 + 1]) for i in range(m)]
i = j = 0
free_start = 0
answer = -1
while i < n or j < m:
    if j >= m or (i < n and first[i][0] <= second[j][0]):
        start, end = first[i]
        i += 1
    else:
        start, end = second[j]
        j += 1
    if start > free_start and start - free_start >= need:
        answer = free_start
        break
    free_start = max(free_start, end)
if answer == -1 and total - free_start >= need:
    answer = free_start
print(answer)
```

### 測資設計方向

- 必測：空檔在最前面（`s = 0`）、空檔在最後面（收尾那段才成立）、空檔長度剛好等於 D、剛好少一分鐘、兩人時段完全重疊、兩人時段完全錯開、其中一人整天忙碌、D = T、n 與 m 都是 50,000 的大測資。
- 常見錯誤殺手：只看其中一人的空檔；忘記檢查最後一段 `[free_start, T)`；用 `>` 而非 `>=` 比較長度導致剛好等於 D 被判無解；把包含在前一段裡的時段（`end` 較小）誤把 `free_start` 往回拉。

## 220 落單的寄物櫃鑰匙

**標籤**：位元運算、XOR、線性掃描　**主要目標**：發現「成對出現」可用 XOR 互相抵銷，把空間壓到 O(1)。

### 題目

游泳池的寄物櫃鑰匙在借出與歸還時各刷一次，所以同一支鑰匙的編號會在紀錄中出現兩次。今天閉館時只有一支鑰匙沒有歸還，它的編號在紀錄中只出現一次。

請從 `N` 筆刷卡紀錄中找出那支鑰匙的編號。

### 輸入格式

第一行是 `N`。第二行是 `N` 個整數，代表刷卡紀錄中的鑰匙編號。

### 輸出格式

一個整數，代表只出現一次的編號。

### 限制

- 3 ≤ N ≤ 200,000，且 N 為奇數
- 1 ≤ 編號 ≤ 10⁹
- 恰有一個編號出現一次，其餘編號都恰好出現兩次

### 範例 1

輸入：

```
5
7 3 7 9 3
```

輸出：

```
9
```

### 範例 2

輸入：

```
3
5 5 12
```

輸出：

```
12
```

### 解法與複雜度

XOR 有兩個性質：`x ^ x = 0`、`x ^ 0 = x`，而且交換律成立。把全部編號 XOR 起來，成對的互相抵銷為 0，只剩下落單的那一個。時間 O(N)，空間 O(1)。

用 `dict` 或 `Counter` 計次也是 O(N)，可以通過，但額外空間 O(N)；雙層迴圈逐一比對是 O(N²)，在 2×10⁵ 會超時。

### 參考解答

```python
# 核心：相同編號兩兩互相抵銷，全部做 XOR 後剩下的就是落單的編號。時間 O(N)，空間 O(1)。
import sys
data = list(map(int, sys.stdin.read().split()))
answer = 0
for value in data[1:1 + data[0]]:
    answer ^= value
print(answer)
```

### 測資設計方向

- 必測：N=3、落單的在最前面、落單的在最後面、編號為 1、編號為 10⁹、成對編號彼此相鄰、成對編號分散在頭尾、N=199,999 的大測資。
- 常見錯誤殺手：雙層迴圈比對（超時）；先排序再找落單（可行但要注意首尾邊界，常在落單值位於最後時出錯）；把 XOR `^` 誤寫成次方或 `+`。

## 221 校園儲值卡結算

**標籤**：雜湊表、模擬、多重排序鍵　**主要目標**：以字典維護多位使用者的狀態，並用多鍵排序輸出唯一結果。

### 題目

校園儲值卡有兩種交易：`deposit`（儲值）與 `spend`（消費）。每位學生的初始餘額是 0，規則如下：

- `deposit x`：餘額增加 `x`。
- `spend x`：若餘額**大於等於** `x`，餘額減少 `x`；若餘額不足，這筆交易整筆失敗，餘額不變，並記為該學生的一次**失敗次數**。

請依交易順序處理完所有紀錄，輸出每位出現過的學生的最終餘額與失敗次數。

### 輸入格式

第一行是 `M`。接下來 `M` 行，每行是 `名字 動作 金額`，動作為 `deposit` 或 `spend`。

### 輸出格式

每位出現過的學生輸出一行：`名字 餘額 失敗次數`，以單一半形空格分隔。排序規則為**餘額由大到小**；餘額相同時**名字字典序由小到大**。

### 限制

- 1 ≤ M ≤ 100,000
- 名字由 1 到 10 個小寫英文字母組成
- 1 ≤ 金額 ≤ 1,000,000

### 範例 1

輸入：

```
6
amy deposit 100
bob deposit 50
amy spend 30
bob spend 80
amy spend 100
cat deposit 50
```

輸出：

```
amy 70 1
bob 50 1
cat 50 0
```

### 範例 2

輸入：

```
2
zoe spend 10
zoe deposit 5
```

輸出：

```
zoe 5 1
```

### 解法與複雜度

用兩個字典分別存餘額與失敗次數，第一次看到名字時初始化為 0。處理完後把字典轉成清單，以 `key=(-餘額, 名字)` 排序。時間 O(M + K log K)（K 是不同學生數），空間 O(K)。

每次查詢都線性掃描清單找學生是 O(M·K)，在 10⁵ 筆交易下會超時，這是本題要擋掉的寫法。

### 參考解答

```python
# 核心：用字典累積每位學生的餘額與失敗次數，最後依餘額遞減、姓名遞增排序。時間 O(M + K log K)，空間 O(K)。
import sys
data = sys.stdin.read().split()
m = int(data[0])
balance = {}
failed = {}
for i in range(m):
    name, action, amount = data[1 + i * 3], data[2 + i * 3], int(data[3 + i * 3])
    if name not in balance:
        balance[name] = 0
        failed[name] = 0
    if action == 'deposit':
        balance[name] += amount
    elif balance[name] >= amount:
        balance[name] -= amount
    else:
        failed[name] += 1
rows = sorted(balance.items(), key=lambda item: (-item[1], item[0]))
print('\n'.join(f'{name} {value} {failed[name]}' for name, value in rows))
```

### 測資設計方向

- 必測：只有一位學生、消費金額剛好等於餘額（應成功且餘額為 0）、消費金額比餘額多 1（應失敗）、第一筆就是消費（餘額 0 失敗）、多位學生餘額相同（驗證名字字典序）、同一學生連續多次失敗、只有 `deposit` 沒有 `spend`、M=100,000 的大測資。
- 常見錯誤殺手：餘額不足時扣成負數或扣到 0；用 `>` 判斷導致「剛好夠付」被判失敗；只依餘額排序而沒有名字 tie-break（輸出不唯一）；用清單線性搜尋學生造成超時；沒有輸出失敗次數為 0 的學生。

## 222 湊滿額的最少品項

**標籤**：回溯、剪枝、字典序　**主要目標**：在指數級搜尋空間中用剪枝與 tie-break 求出唯一解。

### 題目

餐廳的折價券要求消費金額**恰好**等於 `T` 元。菜單上有 `N` 種品項，價格**互不相同**，每種品項最多點一次。

請找出恰好湊到 `T` 元的點法中**品項數最少**的一組。若品項數相同的組合有多組，選擇把價格由小到大排好後**字典序最小**的一組（先比第一個價格，相同再比第二個，依此類推）。若無法恰好湊到 `T` 元，輸出 `NONE`。

### 輸入格式

第一行是 `N T`。第二行是 `N` 個互不相同的整數，代表各品項價格。

### 輸出格式

一行：所選品項的價格，由小到大以單一半形空格分隔；無解輸出 `NONE`。

### 限制

- 1 ≤ N ≤ 18
- 1 ≤ T ≤ 100,000
- 1 ≤ 價格 ≤ 10,000，且價格互不相同

### 範例 1

輸入：

```
5 60
45 20 15 25 35
```

輸出：

```
15 45
```

（`15+45` 與 `25+35` 都是 2 項；字典序取 `15 45`。）

### 範例 2

輸入：

```
2 7
2 4
```

輸出：

```
NONE
```

### 解法與複雜度

先把價格由小到大排序，再對每個品項做「點／不點」的深度優先搜尋，並準備兩個剪枝：

1. **後綴和剪枝**：預先算出 `suffix[i]`（第 i 項之後所有品項的價格總和）。若 `suffix[i] < 剩餘金額`，後面全點也湊不到，直接回頭。
2. **長度剪枝**：目前已選數量再加 1 已經超過目前最佳解的品項數時，不必再往下。

找到 `剩餘金額 == 0` 時，用 `(長度, 價格清單)` 和目前最佳解比較並更新。因為是由小到大列舉，價格清單本身就是遞增的，直接比較清單即可得到字典序 tie-break。最差 O(2^N)，N ≤ 18 時實測在 0.03 秒內完成。

### 參考解答

```python
# 核心：價格排序後深度優先搜尋，並用剩餘金額與目前最佳解剪枝。時間 O(2^N) 最差，空間 O(N)。
import sys
data = list(map(int, sys.stdin.read().split()))
n, target = data[0], data[1]
prices = sorted(data[2:2 + n])
suffix = [0] * (n + 1)
for i in range(n - 1, -1, -1):
    suffix[i] = suffix[i + 1] + prices[i]
best = None
chosen = []

def better(candidate):
    return best is None or (len(candidate), candidate) < (len(best), best)

def search(index, remain):
    global best
    if remain == 0:
        if better(chosen):
            best = chosen[:]
        return
    if index == n or remain < 0 or suffix[index] < remain:
        return
    if best is not None and len(chosen) + 1 > len(best):
        return
    chosen.append(prices[index])
    search(index + 1, remain - prices[index])
    chosen.pop()
    search(index + 1, remain)

search(0, target)
print(' '.join(map(str, best)) if best else 'NONE')
```

> 也可以用 `dp[金額] = (最少品項數, 價格清單)` 的 0/1 背包寫法，複雜度 O(N·T·N)，同樣能過；回溯版本較容易解釋剪枝的作用。

### 測資設計方向

- 必測：N=1 且剛好等於 T、N=1 但湊不到、T 等於所有品項總和（全選）、恰好有兩組同長度組合（驗證字典序）、無解且總和小於 T、無解但總和大於 T（例如全為偶數價格而 T 為奇數，測試剪枝）、N=18 的最大規模、答案只需 1 項但存在多項組合（驗證取最少品項）。
- 常見錯誤殺手：只求「能不能湊到」而沒有輸出組合；tie-break 只比長度不比字典序（輸出不唯一）；沒有剪枝導致最壞情況超時；輸出未依價格由小到大排序。

## 223 修課順序規劃

**標籤**：拓撲排序、最小堆、有向圖　**主要目標**：判斷先修關係是否有循環，並輸出字典序最小的可行順序。

### 題目

系上有 `N` 門課，編號 1 到 `N`。有 `M` 條先修關係，每條是 `a b`，代表「修 `b` 之前必須先修完 `a`」。每學期只修一門課。

請輸出一個滿足所有先修關係的修課順序。若有多種可行順序，輸出**字典序最小**的那一個（也就是每一步都在能修的課裡挑編號最小的）。若先修關係互相矛盾而無法全部修完，輸出 `IMPOSSIBLE`。

### 輸入格式

第一行是 `N M`。接下來 `M` 行，每行兩個整數 `a b`。

### 輸出格式

一行 `N` 個整數，以單一半形空格分隔；無解輸出 `IMPOSSIBLE`。

### 限制

- 1 ≤ N ≤ 100,000
- 0 ≤ M ≤ 200,000
- 1 ≤ a, b ≤ N 且 a ≠ b；同一條先修關係可能重複出現

### 範例 1

輸入：

```
4 3
1 2
1 3
3 4
```

輸出：

```
1 2 3 4
```

### 範例 2

輸入：

```
2 2
1 2
2 1
```

輸出：

```
IMPOSSIBLE
```

### 範例 3

輸入：

```
3 0
```

輸出：

```
1 2 3
```

### 解法與複雜度

建立鄰接表與入度表，把入度為 0 的課全部放進**最小堆**。每次取出編號最小的課加入答案，並把它指向的課入度減 1，減到 0 就推進堆。若最後排出的課程數少於 `N`，代表存在循環，輸出 `IMPOSSIBLE`。時間 O((N + M) log N)，空間 O(N + M)。

用一般佇列（先進先出）也能排出合法順序，但不保證字典序最小，這是本題要求最小堆的原因。

### 參考解答

```python
# 核心：拓撲排序時用最小堆挑出入度為 0 的最小編號，排不完代表有循環。時間 O((N + M) log N)，空間 O(N + M)。
import sys
import heapq
data = list(map(int, sys.stdin.read().split()))
n, m = data[0], data[1]
graph = [[] for _ in range(n + 1)]
indegree = [0] * (n + 1)
for i in range(m):
    a, b = data[2 + i * 2], data[3 + i * 2]
    graph[a].append(b)
    indegree[b] += 1
heap = [course for course in range(1, n + 1) if indegree[course] == 0]
heapq.heapify(heap)
order = []
while heap:
    course = heapq.heappop(heap)
    order.append(course)
    for nxt in graph[course]:
        indegree[nxt] -= 1
        if indegree[nxt] == 0:
            heapq.heappush(heap, nxt)
print(' '.join(map(str, order)) if len(order) == n else 'IMPOSSIBLE')
```

### 測資設計方向

- 必測：M=0（直接輸出 1..N）、N=1、兩門課互為先修（`IMPOSSIBLE`）、只有部分課程形成循環（仍是 `IMPOSSIBLE`）、一條長鏈（順序被完全決定）、重複出現的相同先修關係、先修關係讓編號大的必須排在前面（例如 `5 1`，驗證不是單純輸出 1..N）、N=100,000 與 M=200,000 的大測資。
- 常見錯誤殺手：用一般佇列導致字典序不是最小；忘記檢查排出的課程數是否等於 N（有循環時只印出部分課程）；重複邊讓入度重複扣減的處理錯誤；DFS 遞迴版本在 10⁵ 節點時超過遞迴深度。
