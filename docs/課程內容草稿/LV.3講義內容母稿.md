## H01 資料規模與效率

**Badge**：O(N)　**先備**：LV.2全課、函式、清單　**新能力**：從限制估計操作量，選擇一次走訪與快速查找。

**概念短講：資料規模與效率**：若 N 為 200,000，雙層迴圈約需四百億次比較，通常不可行；一次走訪約二十萬次。看見大型輸入時，要先估算操作量，再選擇資料結構。

**集合 set 〈🐍 Python 實作〉**：集合只保留不重複的值，適合回答「是否看過」。加入與查找的平均時間為 O(1)。

- \`seen = set()\`：建立空集合。
- \`seen.add(5); seen.add(3)\`：加入 5 和 3。
- \`5 in seen\` 得到 \`True\`。
- \`seen.add(5)\` 不會產生第二個 5。
- \`len(seen)\` 得到 \`2\`。

**字典 dict 〈🐍 Python 實作〉**：字典把每個唯一的鍵 key 對應到一個值 value，適合記錄「這個編號出現幾次」或「這個名稱對應什麼資料」。

- \`count = {}\`：建立空字典。
- \`count["apple"] = 3\`：新增鍵值對。
- \`count["apple"] += 1\`：把已有的值更新為 4。
- \`"apple" in count\` 得到 \`True\`，平均查找為 O(1)。
- \`for key in count: print(key, count[key])\` 可走訪所有鍵及對應的值。

**先預測**：N 從 1,000 增加到 10,000，O(N) 約增 10 倍，O(N²) 約增 100 倍。

### 核心題 C：是否有重複編號 🐍 Python 實作

- 輸入：N（最高 200,000）與 N 個整數編號。
- 輸出：有任何重複輸出 YES，全部不同輸出 NO。
- 範例：6 / 8 3 5 8 1 2 → YES。
- 解法：由左至右；若編號已在集合中即可回答，否則加入集合。
- 複雜度：平均 O(N) 時間、O(N) 空間。
- 測試：N=1、重複在相鄰／首尾、全部不同、大量資料。

### 變體 A：不同編號數量 🐍 Python 實作

- 任務：輸出 N 筆編號中相異值的數量。
- 範例：7 / 4 4 2 9 2 2 8 → 4。
- 解法：建立集合後輸出長度。
- 測試：全部相同、全部不同、含負數與 0。

### 變體 B：最常出現的編號 🐍 Python 實作

- 任務：輸出出現次數最多的編號；並列時輸出數值最小者。
- 範例：8 / 5 2 5 3 2 2 5 4 → 2（2 與 5 都三次，取較小）。
- 解法：字典計數，再依「次數較大／次數相同而值較小」更新答案。
- 測試：唯一最多、並列、全都一次、負數並列。

**常見錯誤**：以雙層迴圈比對每一對、只測小資料、B 題忽略 tie-break。  
**通關檢核**：能用估算說明為何 N=200,000 不適合 O(N²)。

## H02 基礎排序：氣泡、選擇、插入

**Badge**：bubble · selection · insertion　**先備**：清單、巢狀迴圈、交換　**新能力**：以比較與交換親手做出一種 O(N²) 排序

**概念短講**：三種基礎排序都靠「比較、交換」。氣泡：相鄰兩兩比較，大的往後換，每一輪把目前最大值推到最後；某一輪完全沒有交換就代表排好了，可以提早停。選擇：每輪找出剩下的最小值，換到最前面，交換次數最少。插入：像整理手上的撲克牌，把新牌往左挪到該放的位置；資料已經接近排好時幾乎不用挪，接近 O(N)。三者最壞都是 O(N²)，N=200,000 時跑不完——這就是下一關要解決的事。本關不使用排序函式。

**先預測**：`[4, 3, 1]` 做一輪氣泡排序後會變成什麼？哪個數已經到達最終位置？答案：`[3, 1, 4]`；4 先和 3 換、再和 1 換，一路被推到最後，這一輪結束時最大值一定歸位。

### 核心題 C：氣泡排序每一輪

- 輸入：N 與 N 個整數。
- 輸出：由小到大做氣泡排序，每完成一輪就輸出一次目前的清單；某一輪沒有發生交換就在該輪後停止。
- 範例：5 / 5 1 4 2 8 → 1 4 2 5 8 / 1 2 4 5 8 / 1 2 4 5 8。
- 解法：由左到右比較相鄰兩數，逆序就交換，每輪結束輸出目前清單；swapped 全程為否代表已排序，提早停止。
- 複雜度：O(N²) 時間、O(1) 額外空間。
- 測試：N=1、已排序（一輪即停）、完全反序（多輪收斂）、一般亂序。

### 變體 A：選擇排序的交換次數

- 任務：輸入 N 與 N 個相異整數，做選擇排序：每輪找出尚未排好部分的最小值，只有不在目前位置時才交換，輸出總交換次數。
- 範例：5 / 5 1 4 2 8 → 2。
- 解法：每輪掃描找出剩餘部分的最小值位置 best，只有 best 不等於目前位置才交換並計數。
- 複雜度：O(N²)。
- 測試：一般資料、已排序（0 次）、小規模反序、完全反序（交換數達上限）。

### 變體 B：插入排序要挪幾次

- 任務：輸入 N 與 N 個整數，做插入排序，每把一個元素往右挪一格就算一次，輸出總挪動次數。
- 範例：5 / 5 1 4 2 8 → 4。
- 解法：把要插入的值存進 cur，向左比較並搬移較大的值，每搬一格記一次，最後把 cur 放回空位。
- 複雜度：O(N²)。
- 測試：一般資料、已排序（0 次）、完全反序（達最大挪動次數）、N=1。

**常見錯誤**：內層迴圈寫到 n-1 使 a[j+1] 越界；交換寫成 a[j] = a[j+1] 再 a[j+1] = a[j]，兩格變成同一個值；swapped 沒有每輪重設，導致永遠不會停。  
**通關檢核**：能說明為什麼第 k 輪結束後，最後 k 個位置一定已經排好。

## H03 進階排序：希爾、合併、快速

**Badge**：gap · merge · partition　**先備**：H02、while、清單　**新能力**：知道 O(N log N) 從哪裡來，並做出三種進階排序的核心步驟

**概念短講**：希爾：先用大間隔做插入排序，讓遠處的值一次跨一大步，間隔逐次縮小到 1，是從 O(N²) 往下走的第一步。合併：一直對半切到只剩一個，再兩兩合併回去；切一半要 log N 層，每層合併共花 N 次，所以是 O(N log N)——這就是這個符號的來源，而且相同值的先後順序不會改變（穩定）。快速：選一個 pivot，把比它小的放左邊、其餘放右邊，再各自排序；平均 O(N log N)，但 pivot 老是選到最大或最小時會退化成 O(N²)。Python 的 sort() 是 Timsort，合併排序加插入排序的混合，穩定且 O(N log N)。本關三題只做核心步驟，完整的遞迴版本等 H11 學完遞迴再回頭看。

**先預測**：合併 `[1, 4, 7]` 與 `[2, 3, 9]`，前三次比較各取出哪個數？答案：1（1 對 2）、2（4 對 2）、3（4 對 3）；每次只比兩邊的「開頭」，取較小者後那一邊往前一格。

### 核心題 C：合併兩個已排序清單

- 輸入：N 與 N 個非遞減整數，再輸入 M 與 M 個非遞減整數。
- 輸出：合併後的非遞減清單，空白分隔；不可使用排序函式。
- 範例：A：1 4 7 9，B：2 4 8 → 1 2 4 4 7 8 9。
- 解法：用兩個指標各自指向兩個清單的開頭，每次取較小者放入答案，一邊用完就把另一邊剩下的全部接上。
- 複雜度：O(N+M) 時間、O(N+M) 空間。
- 測試：長度不同、相同值相鄰（穩定性）、兩清單數值不重疊、含負數。

### 變體 A：希爾排序的一輪

- 任務：輸入 N 與間隔 g，接著輸入 N 個整數，只做間隔 g 的插入排序：位置 i、i+g、i+2g…自成一組，各組各自排好，輸出這一輪之後的清單。
- 範例：間隔 4、8 7 6 5 4 3 2 1 → 4 3 2 1 8 7 6 5。
- 解法：把位置 i、i+g、i+2g…視為同一組，各組各自做插入排序，比較與搬移時一次跨 g 格。
- 複雜度：一輪為 O(N²/g)。
- 測試：一般間隔、g=1（退化為一般插入排序）、間隔不整除 N、已排序資料不受影響。

### 變體 B：快速排序的一次分割

- 任務：輸入 N 與 N 個整數，以第一個數為 pivot，輸出比 pivot 小的數（保持原順序）、pivot、大於或等於 pivot 的其餘數（保持原順序）。
- 範例：5 8 1 9 3 5 2（pivot=5） → 1 3 2 5 8 9 5。
- 解法：掃過其餘元素分成 less 與 ge 兩個清單，最後接成「less、pivot、ge」。
- 複雜度：O(N) 時間、O(N) 空間。
- 測試：一般資料含與 pivot 相等的值、N=1、已排序資料、pivot 為最大值。

**常見錯誤**：一邊用完就停，忘了把另一邊剩下的接上；把希爾的「間隔分組」誤做成「切成連續的幾段」；以為快速排序一定是 O(N log N)。  
**通關檢核**：能說明為什麼合併兩個長度 N 的已排序清單只要 O(N)，並判斷兩邊未排序時是否還能這樣做。

## H04 排序與自訂順序 🐍 Python 實作

**Badge**：sort(key=...)　**先備**：清單、函式、tuple　**新能力**：把題目的優先規則轉成排序鍵。

**概念短講**：H02、H03 看過排序怎麼做；這一關只需要決定依什麼排。排序不是只有由小到大。tuple 是不可變的序列，可用小括號或逗號建立，常用來表示一組不需修改的排序鍵。例如 \`pair = (90, "Amy")\`，\`pair[0]\` 是 \`90\`。Python 比較 tuple 時會先比第一項，相同才比第二項，因此 \`(-90, "Amy") < (-90, "Bob")\` 為 \`True\`。數值要降冪排列時，可在排序鍵中取負號。

**先預測**：將 \`[(90, "Amy"), (85, "Bob"), (90, "Ann")]\` 依分數由高到低排列，同分時依姓名字典序排列，結果是什麼？答案：\`[(90, "Amy"), (90, "Ann"), (85, "Bob")]\`。

### 核心題 C：成績排行榜

- 輸入：N，接著 N 行 name score，姓名不重複。
- 輸出：分數高到低；同分時姓名字典序小到大，每行一個姓名與分數。
- 範例：Amy 90、Bob 95、Ann 90 → Bob 95 / Amy 90 / Ann 90。
- 解法：排序鍵為 (-score, name)。
- 複雜度：O(N log N)。
- 測試：同分、原本已排好、完全反序、單筆。

### 變體 A：依距離排序

- 任務：輸入 N 個整數，依與 0 的距離由近到遠排序；距離相同時較小數在前。
- 範例：-3 1 -1 2 0 3 → 0 -1 1 2 -3 3。
- 解法：排序鍵為 (abs(x), x)。
- 測試：正負成對、含 0、全部同號。

### 變體 B：合併時間區間

- 任務：輸入 N 個閉區間 start end，依 start 排序後，合併重疊或相接區間並輸出。
- 範例：[5,7]、[1,3]、[3,4]、[10,12] → [1,4]、[5,7]、[10,12]。
- 解法：先排序，再和結果尾端比較；若下一段 start ≤ 目前 end 就延伸。
- 測試：完全分離、全部合併、包含關係、相接邊界。

**常見錯誤**：多欄優先順序顛倒、降冪鍵沒取負、B 題未先排序就合併。  
**通關檢核**：能先用中文列出優先規則，再寫出對應排序鍵。

## H05 前綴和與區間查詢

**Badge**：prefix[R] - prefix[L-1]　**先備**：累加、清單索引、H01　**新能力**：用一次預處理換取多次快速查詢。

**概念短講**：令 prefix[i] 表示前 i 筆總和，並令 prefix[0]=0。1 起算閉區間 L 到 R 的總和是 prefix[R]-prefix[L-1]。

**先預測**：資料為 \`[2, 4, 1, 3, 5]\`，以 \`prefix[0] = 0\` 建立前綴和清單，再求 1 起算第 2 到第 4 筆的總和。答案：\`prefix = [0, 2, 6, 7, 10, 15]\`，區間和為 \`prefix[4] - prefix[1] = 8\`。

### 核心題 C：每日用電查詢

- 輸入：N、Q；一行 N 天用電量；Q 行查詢 L R。
- 輸出：每個閉區間的總和。
- 範例：資料 2 4 1 3 5；查詢 1–3、2–5、4–4 → 7、13、3。
- 解法：建立長度 N+1 的前綴和，每題 O(1) 回答。
- 複雜度：O(N+Q) 時間、O(N) 空間。
- 測試：單點、全區間、L=1、R=N、Q 很大。

### 變體 A：區間平均

- 任務：每筆查詢輸出區間整數平均（無條件捨去）。
- 範例：資料 2 4 1 3 5，查詢 2–4 輸出 2。
- 解法：區間總和除以 R-L+1。
- 測試：單點、不能整除；資料限定非負整數，避免負數整除語意干擾。

### 變體 B：固定長度最大總和

- 任務：輸入 N、K 與 N 個整數，輸出任一連續 K 筆的最大總和。
- 範例：6 3 / 2 -1 4 3 -5 6 → 6。
- 解法：以前綴和比較所有長度 K 的區間，或用滑動視窗。
- 測試：K=1、K=N、全負數、最大窗在開頭／結尾。

**常見錯誤**：漏建 prefix[0]、L 少減 1、把區間長度算成 R-L。  
**通關檢核**：能畫前綴陣列並手算至少兩個區間。

## H06 雙指標與滑動視窗

**Badge**：left · right · window　**先備**：H05、while、清單　**新能力**：用兩個單向指標維護變長區間，把 O(N²) 降成 O(N)

**概念短講**：右指標每次把一個新元素納入視窗；條件達成（或超標）時移動左指標把視窗縮小。兩個指標都只往右走、各走最多 N 步，所以是 O(N)。能這樣做的前提是單調：全為正數時，視窗變長總和只會變大、變短只會變小；有負數時這個保證就消失了。H05 的變體「固定長度最大總和」是視窗長度固定的特例，用前綴和就能解；本關的視窗長度會隨條件伸縮。另一種雙指標是從兩端往中間夾，用在已排序的資料上。

**先預測**：資料 `[2, 3, 1, 2, 4, 3]`、S=7。右指標走到第 4 筆（值 2）時視窗是 `[2, 3, 1, 2]`、總和 8，左指標要移動幾次？移完後視窗是什麼？答案：1 次；移掉 2 之後剩 `[3, 1, 2]`、總和 6，不再達標就停，但移動前要先記下長度 4。

### 核心題 C：達標的最短連續日數

- 輸入：N、S 與 N 個正整數銷售量。
- 輸出：總和至少為 S 的最短連續天數；全部加起來仍不足就輸出 0。
- 範例：S=7、2 3 1 2 4 3 → 2。
- 解法：右指標逐一把新元素加入總和；總和達標就用 while 反覆縮左邊、更新最短長度，直到總和低於 S。
- 複雜度：O(N) 時間、O(1) 額外空間。
- 測試：一般資料、總和不足（輸出 0）、N=1、答案為整個陣列。

### 變體 A：兩端往中間夾

- 任務：輸入 N、T 與 N 個嚴格遞增的整數，輸出和恰好為 T 的配對數量。
- 範例：T=10、1 2 3 7 8 9 → 3。
- 解法：左右指標從兩端出發，總和等於 T 就計數並同時內縮，太小就右移左指標，太大就左移右指標。
- 複雜度：O(N)。
- 測試：多組配對、無配對（輸出 0）、只有部分配對、N=2 最小情況。

### 變體 B：最多補 K 個洞

- 任務：輸入 N、K 與 N 個 0 或 1，最多可以把 K 個 0 當成 1，輸出這樣能得到的最長連續全 1 段長度。
- 範例：K=2、1 1 0 0 1 1 1 0 1 1 → 7。
- 解法：右指標擴張視窗，視窗內 0 的個數超過 K 就用 while 縮左邊，全程記錄視窗長度的最大值。
- 複雜度：O(N)。
- 測試：一般資料、K=0（退化為找最長原始連續 1 段）、全部為 0 且可全補、K 小於可補需求。

**常見錯誤**：縮左邊用 if，只縮一格就離開；資料含負數時仍套用滑動視窗；兩端往中間夾時找到一組後只移動一邊，造成重複計算。  
**通關檢核**：能說明為什麼縮左邊要用 while 而不是 if，並指出資料含負數時這個方法哪裡會壞掉。

## H07 二分搜尋

**Badge**：binary search　**先備**：排序、while、索引　**新能力**：在單調條件中每次排除一半範圍。

**概念短講**：二分搜尋需要「答案在某點前後呈單調變化」。不變量要說清楚：答案仍在目前搜尋範圍內。核心問題常是找任一值、第一個符合或最後一個符合。

**先預測**：在 \`[1, 4, 7, 10, 13]\` 中以二分搜尋找 7。第一次比較的中間值是什麼？最多需要幾次比較？答案：中間值就是 7，本例 1 次即找到；任意目標在這 5 筆資料中最多需 3 次比較。

### 核心題 C：第一個達標日

- 輸入：N、目標 T，及 N 個非遞減累積值。
- 輸出：第一個大於等於 T 的 1 起算位置；不存在輸出 -1。
- 範例：6 10 / 2 5 5 9 12 18 → 5。
- 解法：以半開或閉區間找 lower bound，找到時仍往左縮。
- 複雜度：O(log N)。
- 測試：答案在第一／最後、重複值、全部不足、剛好相等。

### 變體 A：查找確切數字

- 任務：在嚴格遞增清單找 X；存在輸出 1 起算位置，否則 -1。
- 範例：1 4 7 10 13 中找 7 → 3。
- 解法：比較中點後保留左半或右半。
- 測試：首尾、中央、不存在於兩值之間。

### 變體 B：最小可行速度

- 任務：有 N 份工作量，每小時可完成 K 單位，每份需 ceil(work/K) 小時；求在 H 小時內完成的最小正整數 K。
- 範例：工作量 3 6 7 11，H=8 → 4。
- 解法：速度越大所需時間不會增加，對 K=1 到 max(work) 二分答案。
- 測試：H=N、答案 1、答案為最大工作量、除不盡。

**常見錯誤**：資料不具單調性仍硬用二分、更新邊界沒有排除 mid、核心題找到就停止而非繼續向左。  
**通關檢核**：能先寫出單調敘述與搜尋範圍，再動手寫迴圈。

## H08 堆疊

**Badge**：stack　**先備**：清單、字串走訪　**新能力**：用後進先出保存尚未完成的工作。

**概念短講**：堆疊像一疊盤子，最後放上去的會最先被拿起，這種規則叫「後進先出」。Python 可以直接用 list 當堆疊：\`append(x)\` 把資料放到頂端，\`pop()\` 移除並取回頂端資料。

**先預測**：追蹤字串 \`"([)]"\`。讀到 \`(\`、\`[\` 時堆疊依序為什麼？程式在讀到哪個字元時第一次能確定錯誤？答案：堆疊依序為 \`['(']\`、\`['(', '[']\`；讀到第三個字元 \`)\` 時，它與頂端 \`[\` 不配對。

### 核心題 C：括號是否正確

- 輸入：一個只含 ()[]{} 的非空字串。
- 輸出：括號成對且順序正確輸出 YES，否則 NO。
- 範例：{[()]} → YES；([)] → NO。
- 解法：左括號入堆疊；右括號必須和堆疊頂端配對；最後堆疊需為空。
- 複雜度：O(N)。
- 測試：剩餘左括號、開頭右括號、錯誤交叉、深層巢狀。

### 變體 A：取消上一筆

- 任務：輸入一串整數；正數代表記錄，0 代表取消最近一筆。保證取消時有資料。輸出最後剩餘數字總和。
- 範例：3 5 0 2 4 0 6 → 11。
- 解法：正數 append、0 pop，最後 sum。
- 測試：連續取消、全部取消、沒有取消。

### 變體 B：下一個更大值

- 任務：對每個數字，輸出右側第一個比它大的值；不存在輸出 -1。
- 範例：2 1 5 3 4 → 5 5 -1 4 -1。
- 解法：單調堆疊保存尚未找到答案的索引；每個索引最多進出一次。
- 複雜度：O(N)。
- 測試：遞增、遞減、相等值、交錯。

**常見錯誤**：pop 前沒檢查空堆疊、配對只看是否為右括號、B 題把「第一個」誤成「右側最大」。  
**通關檢核**：能逐步畫出堆疊頂端，並說明為何 B 題不是 O(N²)。

## H09 圖的表示法與樹

**Badge**：鄰接表 · tree　**先備**：清單、二維清單、H04 排序　**新能力**：把「誰跟誰相連」存成鄰接表，並認得樹

**概念短講**：圖＝節點＋邊。網格是圖的一種，但捷運站、好友關係沒有上下左右。三種存法：邊列表，直接把輸入的每一行存起來，找鄰居要掃過全部的邊；鄰接矩陣，N×N 的表格，查「兩點是否相連」只要 O(1)，但要 N² 的空間；鄰接表，每個節點一份鄰居清單，空間 O(N+M)，列出鄰居最快。雙向的路要加兩次：adj[u] 加 v、adj[v] 加 u。樹是 N 個節點、N−1 條邊、連通且沒有環的圖；指定根以後，除了根，每個節點恰好有一個父節點。本關只建表、讀表，走訪留給 H10 的 BFS 與 H11 的 DFS。

**先預測**：只有兩條邊 `1 2` 與 `2 3`，鄰接表中 `adj[2]` 裡有誰？為什麼每條邊要加兩次？答案：`[1, 3]`；路是雙向的，站在 1 要看得到 2，站在 2 也要看得到 1。

### 核心題 C：每個地點的鄰居

- 輸入：N、M 與 M 條雙向道路 u v。
- 輸出：節點 1 到 N 依序輸出鄰居數量，接著輸出鄰居編號由小到大；沒有鄰居的節點只輸出 0。
- 範例：N=4、邊 1-2、1-3、2-3、3-4 → 2 2 3 / 2 1 3 / 3 1 2 4 / 1 3。
- 解法：建立 N+1 份鄰接清單，每讀一條邊就同時把兩端互相加入對方的清單，輸出前先排序每個節點的鄰居。
- 複雜度：建表 O(N+M)、含排序輸出 O(N + M log M)、空間 O(N+M)。
- 測試：一般圖、無邊（全部孤立）、最小情況 N=2、含孤立節點。

### 變體 A：樹的葉節點

- 任務：輸入 N，接著一行是節點 2 到 N 的父節點編號（根是 1），輸出葉節點的數量；葉節點就是沒有任何子節點的節點。
- 範例：父節點 1 1 2 2 3（節點 2~6） → 3。
- 解法：統計每個節點被當成父節點的次數，次數為 0 的節點就是葉節點。
- 複雜度：O(N)。
- 測試：一般樹、N=2 最小情況、鏈狀樹、星狀樹（多個葉節點）。

### 變體 B：每個節點的深度

- 任務：輸入格式同上，且保證每個節點的父節點編號小於自己，根的深度為 0，輸出節點 1 到 N 的深度。
- 範例：父節點 1 1 2 2 3 → 0 1 1 2 2 2。
- 解法：父節點編號一定較小，所以由小到大遞推：某節點深度等於其父節點深度加 1。
- 複雜度：O(N)。
- 測試：一般樹、N=2 最小情況、鏈狀樹（深度遞增）、星狀樹（深度皆為 1）。

**常見錯誤**：雙向邊只加一次，另一個方向查不到；節點從 1 編號卻只開 N 格清單，最後一個節點越界；以為鄰居會自動照編號排好。  
**通關檢核**：能估算 N=100,000、M=100,000 時，鄰接矩陣與鄰接表各需要多少格空間。

## H10 佇列與廣度優先搜尋

**Badge**：deque / BFS　**先備**：二維清單、座標、集合　**新能力**：以先進先出逐層擴展，求無權圖最少步數。

**概念短講**：BFS 先處理距離較近的狀態。狀態一加入佇列就標記 visited，避免同一格重複入列。四方向網格每移動一次成本相同，第一次到終點即為最少步數。

**先預測**：對下列 3×3 地圖從 S 做四方向 BFS，不能走 \`#\`，最少第幾步到 T？答案：4 步。

\`S.. / .#. / ..T\`

### 核心題 C：網格最短路

- 輸入：R、C 與 R 行地圖；S 起點、T 終點、. 可走、# 牆，只能上下左右。
- 輸出：S 到 T 的最少步數；無法到達輸出 -1。
- 範例：3×4 地圖 S... / .##. / ...T → 5。
- 解法：佇列保存座標與距離，或另建距離表。
- 複雜度：O(RC)。
- 測試：相鄰、無路、單一路徑、多條路、起終點在邊界。

### 變體 A：擴散需要幾分鐘

- 任務：地圖中可有多個起點 F，每分鐘同時向四鄰 . 擴散，# 不可通過；輸出覆蓋所有可達空格所需分鐘。
- 解法：所有 F 一開始同時入列，做多源 BFS，答案為最大距離。
- 測試：單源、多源、沒有空格、隔離區域（只計可達）。

### 變體 B：最少轉乘站數

- 任務：給 N 個站與 M 條雙向連線，輸入起點 S、終點 T；每走一條連線算 1，輸出最少步數，無路 -1。
- 解法：建立鄰接清單後 BFS。
- 測試：S=T、直接相連、存在環、圖不連通。

**常見錯誤**：出列才標記導致大量重複、用 stack 變成 DFS、把 BFS 當成可處理不同權重。  
**通關檢核**：能解釋「第一次到達即最短」所依賴的等權條件。

## H11 遞迴與深度優先搜尋

**Badge**：recursion / DFS　**先備**：函式、堆疊觀念、二維資料　**新能力**：定義終止條件與較小子問題，深入走訪連通狀態。

**概念短講**：遞迴有三個要素：①基底案例，什麼時候停止；②將問題變成規模更小的同類問題；③用小問題的答案組合成大問題的答案。Python 的預設遞迴深度約為 1000，資料可能形成很深的呼叫鏈時，應考慮改用迴圈與手動堆疊；只有在確認記憶體與輸入上限後，才考慮 \`sys.setrecursionlimit\`。

**先預測**：將 \`digit_sum(123)\` 展開為 \`3 + digit_sum(12)\`，再繼續展開到基底案例。答案：\`3 + 2 + digit_sum(1) = 3 + 2 + 1 = 6\`。

### 核心題 C：連通色塊大小

- 輸入：R、C、起點座標，以及只含 0/1 的格子；由值為 1 的起點上下左右移動。
- 輸出：與起點連通的 1 格數；起點為 0 則輸出 0。
- 解法：DFS 遇越界、0 或 visited 即返回；否則標記並累加四鄰結果。
- 複雜度：O(RC)。
- 測試：起點為 0、單格、整張連通、被 0 分隔。

### 變體 A：遞迴數位和

- 任務：以遞迴函式計算非負整數各位數總和。
- 範例：5072 → 14。
- 子問題：digit_sum(n) = n % 10 + digit_sum(n // 10)；終止條件為 n < 10。
- 測試：0、個位數、尾端多個 0。

### 變體 B：迷宮是否可達

- 任務：輸入含 S、T、.、# 的地圖，只回答是否存在路徑，輸出 YES/NO。
- 解法：DFS 或明確的手動 stack；找到 T 可提早結束。
- 測試：直達、死路、環、狹長路徑。

**常見錯誤**：沒有終止條件、標記 visited 太晚而互相遞迴、將遞迴深度設計到超出 Python 限制。  
**通關檢核**：能在寫遞迴前說出「參數代表什麼、何時停止、子問題如何變小」。

## H12 記憶化遞迴：從遞迴到 DP

**Badge**：memo · top-down　**先備**：H11 遞迴、清單　**新能力**：用備忘錄消除重複子問題，並看出它與 DP 是同一件事

**概念短講**：爬樓梯方法數 ways(n) = ways(n-1) + ways(n-2)。直接遞迴時 ways(25) 要呼叫 150,049 次，因為 ways(23)、ways(22)…被重算了很多遍。備忘錄：算過就存進 memo[n]，下次直接取，每個 n 只真正算一次，總共 O(N)。備忘錄用清單 memo = [-1] * (n + 1) 就好，三種語言都做得到；Python 也可以用 dict 或 @lru_cache。把「誰先算好」反過來，從小到大填表，就是 H14 的動態規劃——兩者是同一件事的兩種寫法。

**先預測**：不用備忘錄時，`ways(5)` 總共會呼叫 `ways(2)` 幾次？（`ways(1)=1`、`ways(2)=2` 是基底）答案：3 次；`ways(4)` 呼叫一次，`ways(3)` 出現兩次、各再呼叫一次。

### 核心題 C：爬樓梯方法數

- 輸入：N（1 ≤ N ≤ 30），每次可以走 1 階或 2 階。
- 輸出：從地面走到第 N 階的方法數；請用遞迴函式搭配備忘錄完成。
- 範例：N=5 → 8。
- 解法：函式開頭先處理基底 n=1、n=2，再查備忘錄，查不到才計算 ways(n-1)+ways(n-2) 並存入備忘錄。
- 複雜度：O(N) 時間、O(N) 空間。
- 測試：一般值、N=1 與 N=2 基底、N=30（大數值驗證備忘錄）。

### 變體 A：呼叫次數對照

- 任務：輸入 N（N ≤ 25），第一行輸出不用備忘錄時函式的總呼叫次數，第二行輸出用備忘錄時的總呼叫次數；查到備忘錄也算一次呼叫。
- 範例：N=25 → 150049 / 47。
- 解法：分別實作不加備忘錄與加備忘錄的遞迴，各自在函式開頭計數呼叫次數再輸出比較。
- 複雜度：不用備忘錄呈指數成長，用備忘錄為 O(N)。
- 測試：較大 N 凸顯差距、中等 N、小 N、N=1 基底。

### 變體 B：翻成由下而上

- 任務：輸入 N（N ≤ 60）與長度 N 的字串代表第 1 到 N 階，"#" 是封閉階梯不能踩、"." 可以踩，每次走 1 階或 2 階，從第 0 階出發，輸出走到第 N 階的方法數；不使用遞迴，由小到大填 dp。
- 範例：N=6、`..#...` → 4。
- 解法：由小到大填 dp，dp[0]=1，遇到封閉階梯直接填 0，否則加總 dp[i-1] 與（若存在）dp[i-2]。
- 複雜度：O(N) 時間、O(N) 空間。
- 測試：一般含封閉階梯、全部可踩、封閉階梯導致無法到達（輸出 0）、起點封閉但仍有路徑。

**常見錯誤**：先遞迴再查備忘錄，備忘錄形同虛設；備忘錄初值設成 0，但答案本身可能是 0，被誤當成「還沒算」；ways(1) 或 ways(2) 的基底寫錯，整串答案都會偏掉。  
**通關檢核**：能說明查備忘錄為什麼要放在遞迴呼叫之前。

## H13 貪心策略

**Badge**：greedy　**先備**：排序、區間、反例測試　**新能力**：辨認可證明安全的局部選擇。

**概念短講**：貪心不是「看起來最好就選」。必須說明這個選擇不會讓未來更差。活動安排中，每次選最早結束的相容活動，會留下最多後續空間。

**先預測**：活動為 \`[1,3)\`、\`[2,5)\`、\`[3,4)\`。依最早結束選擇時會選哪些？為什麼先選 \`[1,3)\` 不會讓後面的選擇變少？答案：選 \`[1,3)\` 與 \`[3,4)\`；最早結束會為未來留下不小於其他第一個選擇的空間。

### 核心題 C：最多不衝突活動

- 輸入：N 個半開區間 [start,end)。
- 輸出：最多可參加的活動數；上一場 end ≤ 下一場 start 可相接。
- 範例：[1,3)、[2,5)、[3,4)、[4,7)、[6,8) → 3。
- 解法：依 end 由小到大排序，依序選擇 start ≥ last_end 的活動。
- 複雜度：O(N log N)。
- 測試：全不衝突、全部重疊、相接、相同結束時間。

### 變體 A：最少硬幣（特定幣制）

- 任務：幣值固定為 50、10、5、1，輸入非負金額，輸出最少硬幣數。
- 解法：由大到小盡量取；題目限定在可證明適用的幣制。
- 測試：0、剛好一枚、需要各種幣值。

### 變體 B：最少會議室

- 任務：N 個半開會議區間，求同時容納所有會議所需最少房間數。
- 解法：開始與結束事件排序，或用最小堆維護目前最早結束時間；end 等於 start 時先釋放。
- 測試：全分離、全重疊、端點相接、同起點。

**常見錯誤**：核心題依最早開始選、把任意硬幣系統都當可貪心、B 題端點同時發生順序錯。  
**通關檢核**：能提供一個反例推翻錯誤的局部策略，並用交換想法解釋正確策略。

## H14 動態規劃

**Badge**：dp[state]　**先備**：陣列、遞推、H01　**新能力**：定義狀態與轉移，保存重複子問題答案。

**概念短講**：先寫一句完整狀態定義，再決定初始值與轉移。若 dp[i] 的意思不清楚，程式通常會出現錯一格或基底錯誤。

**先預測**：費用為 \`[10, 15, 20]\`，令 \`dp[i]\` 表示踩到 Python 索引 i（人類習慣的第 i+1 階）的最低費用。\`dp[0]\`、\`dp[1]\`、\`dp[2]\` 分別是什麼？到達樓頂的答案是什麼？答案：\`dp = [10, 15, 30]\`，可從第 2 階直接走到樓頂，最低費用為 15。

### 核心題 C：最低爬樓成本

- 輸入：N 與 N 階成本；可從第 1 或第 2 階開始，每次走 1 或 2 階，踩到一階就付該階成本，求到達樓頂（第 N 階之後）的最低成本。
- 範例：5 / 10 15 20 1 5 → 16。
- 狀態：dp[i] 為踩到索引 i（第 i+1 階）的最低成本；由前 1 或前 2 階轉移，答案取最後兩階較小者。
- 複雜度：O(N)；可壓縮至 O(1) 空間。
- 測試：N=2、選跳一步／兩步、費用差距大、全部相同。

### 變體 A：不相鄰最大總和

- 任務：輸入 N 個非負整數，選一些互不相鄰的項目，使總和最大。
- 範例：2 7 9 3 1 → 12。
- 狀態：考慮前 i 項的最大值；轉移為不選第 i 項或選它加上前 i-2 項。
- 測試：單筆、兩筆、交錯大小、全 0。

### 變體 B：硬幣組合數

- 任務：給定互異正整數幣值與目標 S，求不計順序的組合數。
- 範例：幣值 1 2 5、S=5，答案 4。
- 狀態：dp[s] 為湊出 s 的方法數；外層先走幣值才能避免把排列重複計算。
- 測試：S=0、無法湊成、單一幣值、順序重複陷阱。

**常見錯誤**：沒寫狀態定義就套公式、基底 dp[0] 設錯、B 題內外迴圈反轉。  
**通關檢核**：能完整說出狀態、初始值、轉移、計算順序與答案位置。

## H15 二維 DP 與子序列 DP

**Badge**：dp[r][c] · dp[i][j]　**先備**：H14 一維 DP、二維清單　**新能力**：兩個索引的狀態、二維 dp 表與填表順序

**概念短講**：網格路徑：dp[r][c] 是走到 (r, c) 的最佳值；只能從上方或左方來，所以由上到下、由左到右填，每一格都只看已經填好的兩格。子序列：最長共同子序列的 dp[i][j] 是「A 的前 i 個字」與「B 的前 j 個字」的答案；字元相同取 dp[i-1][j-1] + 1，否則取 dp[i-1][j] 與 dp[i][j-1] 的較大者。多開一列一欄的 0 當邊界，跟 prefix[0] = 0 是同一個想法。子序列可以跳著選、但不能換順序，和「連續子字串」不同。最長遞增子序列的狀態只有一維，但每一格要回看前面所有位置，是 O(N²)。

**先預測**：2×2 地圖 `1 2 / 3 4`，dp 表的四格各是多少？答案：`1 3 / 4 7`；第一列只能從左邊來、第一欄只能從上面來，右下角取 3 和 4 的較小者再加 4。

### 核心題 C：最低通行費

- 輸入：R、C 與 R 行、每行 C 個非負整數通行費。
- 輸出：從左上角出發，每步只能向右或向下，走到右下角（含起點與終點都要付費）的最少總費用。
- 範例：3×3 費用網格 1 3 1 / 1 5 1 / 4 2 1 → 7。
- 解法：dp[i][j] 只能從上方或左方來，先填好第一列與第一欄，再取上方與左方較小者加上本格費用。
- 複雜度：O(R×C) 時間與空間。
- 測試：一般網格、1×1 最小情況、2×2、單列（只能向右走）。

### 變體 A：有障礙的路徑數

- 任務：輸入 R、C 與由 "." 與 "#" 組成的地圖，"#" 不能走，只能向右或向下，輸出從左上角走到右下角的路徑數；起點或終點是 "#" 時輸出 0。
- 範例：3×3 地圖 ... / .#. / ... → 2。
- 解法：障礙格 dp 直接為 0，其餘格子的路徑數等於上方與左方路徑數相加。
- 複雜度：O(R×C)。
- 測試：一般含障礙、1×1 最小情況、起終點被封鎖（輸出 0）、無障礙網格。

### 變體 B：最長共同子序列

- 任務：輸入兩行小寫英文字串，輸出兩者最長共同子序列的長度；子序列可以跳著選，但不能改變原本的先後順序。
- 範例：abcde 與 ace → 3。
- 解法：dp[i][j] 表示 A 前 i 字與 B 前 j 字的最長共同子序列；字元相同取 dp[i-1][j-1]+1，否則取上方與左方較大者。
- 複雜度：O(N×M)。
- 測試：一般子序列、完全相同、完全不重疊（輸出 0）、含重複字元。

**常見錯誤**：第一列、第一欄沒有特別處理，Python 的 dp[-1] 不會報錯，會默默讀到最後一列；最長共同子序列的字元索引與 dp 索引差 1，寫成 a[i] 就會錯開一格；把子序列當成連續子字串。  
**通關檢核**：能說明為什麼填表順序必須是「由上到下、由左到右」，並指出倒過來填會發生什麼事。

## H16 圖搜尋綜合建模

**Badge**：model → traverse　**先備**：H01–H15，尤其 BFS／DFS　**新能力**：從題意自行定義節點、邊與狀態，選擇搜尋方式並分析成本。

**概念短講**：這一關不引入新工具，而是練習建模。看到題目時先回答四個問題：①節點是什麼？②邊是什麼？③每次走訪需要記錄或回傳什麼資訊？④需要逐層的最短距離 BFS，還是只需完整走訪的 DFS？

**先預測**：下列 3×3 地圖中，上下左右相連的 1 屬於同一區域。共有幾個區域？最大區域有幾格？答案：3 個區域，最大區域 3 格。

\`110 / 010 / 101\`

### 核心題 C：災後通訊區域

- 輸入：R×C 地圖，1 表示仍可通訊、0 表示中斷；上下左右相鄰的 1 屬同一區域。
- 輸出：第一行區域數，第二行最大區域格數；沒有 1 時兩行皆 0。
- 範例：3×5 地圖 11010 / 01011 / 10000 → 3 / 3。
- 建模：每個 1 格是節點，相鄰為邊；掃描未拜訪 1 時啟動一次 DFS/BFS。
- 複雜度：O(RC)。
- 測試：全 0、全 1、單格、多個同大小區域、棋盤狀。

### 變體 A：好友群組

- 任務：N 人、M 條雙向好友關係，輸出連通群組數與最大群組人數。
- 解法：鄰接清單＋DFS/BFS；孤立的人也算一組。
- 測試：無邊、全連通、多群。

### 變體 B：島嶼邊界總長

- 任務：0/1 地圖中所有 1 格代表陸地；每個陸地格的四邊若面向邊界或 0，就貢獻 1。輸出總周長。
- 解法：走訪每個 1 格並檢查四個方向；不需要搜尋連通性。
- 測試：單格、長條、實心矩形、中空形狀、多座島。

**常見錯誤**：把對角線當相鄰、只從左上角搜尋、重複拜訪、看到網格就不加判斷地套 BFS。  
**通關檢核**：能先寫出節點、邊、visited、每次搜尋的回傳資訊，並說明為何 B 題用直接走訪更簡單。
