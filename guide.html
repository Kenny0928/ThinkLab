Judge Guide

驗資到底在檢查什麼？

交出去的程式碼，是被「機器」一字一句對答案，不是被人看過就給分。這頁用互動示範，帶你看懂測資怎麼被吃掉、輸出怎麼被比對。

INPUT 沒有人坐在鍵盤前面打字。驗資的時候，電腦把整包測資一次餵給你的程式，程式要自己一段一段把它讀出來。
OUTPUT 你的輸出要跟標準答案一字不差——包括空格、換行、大小寫。唯一會被原諒的，是整份輸出「最後面」多出來的空白或換行；中間任何一個字元不一樣，都算錯。

只要 stderr（錯誤訊息）有任何內容，不管答案對不對，一律先判成 RE。

03 · 本頁主角

要讀幾次？

同一筆測資，Scratch 和 Blockly 左右並排。按「下一步」看測資怎麼被一步步吃掉。

問太多次：測資被讀光了還要再讀，程式當場壞掉，變成 RE。點上面「兩邊都再多問一次看看」，會看到兩邊各自真正丟出來的錯誤訊息。
問太少次：沒關係。剩下沒讀到的測資會直接被丟掉，不影響結果——只要你已經讀到的部分算出了正確答案。

ThinkLab 全部 214 題，沒有一題需要讀到測資的最後一個字。每一題要讀幾次，都是算得出來的固定數字。

04 · Scratch

詢問積木在問誰？

驗資的時候沒有人會看到提示字，也沒有人會在舞台上打字回答——「詢問」積木其實是直接從測資裡拿下一個詞。

詢問 你叫什麼名字？ 並等待 詢問的答案
說出 你好 想著 你好

提示字只有你自己看得到

「你叫什麼名字？」這句話不會出現在輸出裡，驗資的時候也沒有人會看到它。

一個詢問＝一個詞

空格和換行都算分隔。輸入「3 5」，第一次詢問拿到「3」，第二次詢問拿到「5」——跟 Blockly 一次吃一整行完全不同。

「詢問的答案」只記得最後一次

第二次詢問一問完，第一次的答案就被蓋掉了。要保留第一次的值，必須先把它存進一個變數。

「說出」才有輸出，「想著」完全沒有

「說出」會輸出一行並自動換行；「想著」不管想什麼，都不會出現在輸出裡。

05 · Blockly

一次讀一整行

「要求輸入文字」積木對應 Python 的 input()：一塊接住的是一整行文字，中間的空格都保留。

要求輸入文字 請輸入 A 和 B →
1input()
輸出答案 A + B 然後換行 →
1print(A + B, end='\n')
要求輸入數字 請輸入一個數字 →
1float(input())

一塊＝一整行

放一塊「要求輸入文字」，就吃掉測資的一整行，直到換行為止。

提示字同樣不會進輸出

積木上寫的提示字只是給你自己看的說明，生成的程式碼裡根本沒有這段文字。

一行有兩個數字，要先拆開

把讀到的整行接到清單分類的「從文本製作清單 用分隔符」，分隔符填一個空格，再用索引 0、索引 1 分別取出兩個值（索引從 0 開始）。

「要求輸入數字」會變成 3.0

這塊積木對應 float(input())，就算輸入是整數，印出來也會多一個 .0。要拿到整數，請用「要求輸入文字」再接「轉成 整數」。

06 · 容易忽略

答案都是文字

讀進來的每一段資料，一開始都是文字，不是數字。忘記轉換，加法就會變成「接字串」。

"1" + "1" = "11" 忘記轉成數字：文字接文字
1 + 1 = 2 轉成數字之後：正常相加

Scratch：運算子積木很聰明

「+」「−」「×」「÷」這類運算子積木，看到文字裡是數字時會自動當數字算，所以大部分時候不用特別轉換。但「字串組合」是把文字接起來，不會相加——要算加法就得用「+」積木。

Blockly：要自己轉型

讀進來的每一段文字，要接到「轉成 整數」（或「轉成 小數」）才會變成真正的數字，才能拿去做四則運算或大小比較。

07 · 對答案

常見錯誤對照

綠色是標準答案，紅色是常見的錯誤輸出。差一個字元，就是 WA。

多印了提示字

期望8
你的請輸入答案：8

自己多印出來的說明文字，也會被當成輸出的一部分，跟答案對不起來。

少一個換行

期望Yes⏎No
你的YesNo

只有整份輸出「最後面」的換行會被原諒，中間漏掉的換行不會。

多一個空格

期望3 5
你的3 5

中間多出來的空格不在「最後面」，一樣算不一樣的字元。

用了「想著」

期望89
你的（空白）

「想著」完全不會輸出任何東西，該有的那一行答案整個不見了。

大小寫不同

期望Yes
你的yes

比對不會幫你忽略大小寫，Yes 跟 yes 是兩個不同的答案。

全形空格

期望3 5
你的3　5

全形空格「　」和半形空格是不同的字元，比對時當然對不起來。

08 · 判題結果

看懂 AC / WA / TLE / RE

AC

Accepted。輸出跟標準答案一字不差（只原諒最後面的空白與換行）。

WA

Wrong Answer。程式順利跑完，但輸出跟標準答案對不起來，哪怕只差一個字元。

TLE

Time Limit Exceeded。程式跑太久，通常是迴圈次數抓錯或忘記結束條件。

RE

Runtime Error。程式執行中壞掉了。最常見的原因就是問太多次——測資被讀光了，程式還在硬要讀下一個。
